# Locked requirement files

These lockfiles are generated by `uv pip compile … --generate-hashes` (see the header of
each file for the exact command) and are installed everywhere with `--require-hashes`.

- `build.in` / `build.lock` — the minimal environment for reproducible wheel builds.
- `container.lock` — the runtime image dependency set (dashboard extra, linux platform).

## Auditing locally

CI audits these with pip-audit's `--no-deps` mode. To reproduce locally:

```bash
pip-audit --no-deps --disable-pip -r requirements/container.lock
pip-audit --no-deps --disable-pip -r requirements/build.lock
```

Do **not** run plain `pip-audit -r requirements/container.lock`: the lock contains
direct-URL wheel entries combined with `--require-hashes`, which pip's resolver rejects
("all requirements must have their versions pinned with =="). The `--no-deps` mode skips
resolution and audits the pinned versions directly — the same coverage CI enforces.
